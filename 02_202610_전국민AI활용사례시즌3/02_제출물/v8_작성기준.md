# 초안 v8 작성 기준 (2026-10-23 밤, 현재 판단)

> v6 기준과 그 뒤 사용자 결정, 접수 화면 확인 결과를 모두 담았다. 근거는 사실목록_v1.md. 내용은 사실이어야 하지만, 대화나 장면을 그대로 옮길 필요는 없다. 처음 읽는 심사위원이 이해하는 말로 설명한다.

## 1. 핵심
새 AI 서비스를 써 보며 화면 캡처와 녹화를 고르지 않고 다 남겼다. 시간순 정리는 AI가 맡았다. 그래서 서비스를 써 보는 흐름이 끊기지 않았고, 그 기록을 기초 자료로 예전 방식이면 분량을 줄이거나 늦췄을 사용기 책을 냈다.
- "흐름"은 "책 쓰는 흐름"이 아니다. 먼저 서비스를 써 보는(실습) 흐름이고, 넓게는 써 보기부터 원고까지 전체 작업의 흐름이다
- 캡처와 녹화는 책을 쓰기 위한 기초 자료였다
- 사람은 판단을 안 한 것이 아니라 판단을 쓰는 곳을 바꿨다. 예전에는 무엇을 찍을지 판단했고, 이번에는 그 판단을 내려놓고 써 보는 방향(시나리오를 바꿀지)과 공개할 그림에 판단을 썼다

## 2. 접수 칸 (접수 화면 순서, 10-23 확인)
- 공모 분야: 업무 생산성 개선을 위한 AI 활용
- 사례 제목 (안내 글 "AI를 활용한 사례를 한 문장으로 표현해주세요"): 아래로 고정(임시). 바꾸지 않는다
  새 AI 서비스를 써 보며 화면 캡처 600여 장을 남기고, AI에게 정리를 맡겨 사용기 책을 냈습니다
- 활용한 AI 도구 (한 줄 입력칸, 안내 글 "예: ChatGPT, Upstage Solar, 뤼튼, 코파일럿 등"): 도구 이름 + 무엇에 썼는지 한 줄. 150자 안. Claude Code만 쓴다(Codex는 기록 정리에 쓰지 않았으므로 맨 끝 AI 고지에만). 책의 구성·문장을 AI가 썼다는 말, 사람이 한 일은 이 칸에 쓰지 않는다
- 한 줄 소개 (안내 글 "사례를 짧게 소개해주세요 (목록에 노출됩니다)", 200자 안): 제목과 겹치지 않게. 예전 방식(필요한 부분만 골라 캡처하고 직접 고침, 빠진 화면, 기억해야 함), 녹화도 남김, 써 보는 동안 멈추지 않음, 예전이면 줄이거나 늦췄을 책
- 활용 사례 내용: 소제목은 접수 화면의 다섯 질문을 그대로 쓴다. 그 뒤에 "안전하게 쓰기 위해 지킨 것", "AI를 어디까지 썼는지". 3,000~4,000자
  ① 어떤 상황에서 AI를 활용했나요?
  ② 어떤 AI를 어떻게 활용했나요?
  ③ 활용 결과 어떤 변화가 있었나요?
  ④ 나만의 방식 또는 개선 포인트는 무엇인가요?
  ⑤ 다른 사람도 따라 할 수 있나요?

## 3. 쓰지 않는 것
- 개인정보 보호(사용자 결정): 책 제목, 판매처(위키독스·서점), 판매 링크, 서비스 이름(dots), 서비스 회사(OpenAI), 책 권수("여섯 번째", "다섯 권"), 원고 작성 기간
- 사실과 다르거나 근거 없는 말: "캡처 2,000여 장"(직접 찍은 것은 600여 장), "1,900여 장", "제때 나왔다", "일정도 줄이지 않고", "빠짐없이", "완벽하게", "믿을 수 있다", 시나리오를 바꾼 이유("서비스 반응을 보고"), 채팅형 AI로 해 봤다는 말
- 녹화를 "단계별 폴더에 넣었다"고 쓰지 않는다. 단계별 폴더에 넣은 것은 캡처이고, 녹화는 영상 파일로 따로 모았고 AI가 거기서 장면을 뽑았다
- 대화 원문 인용, 날짜별 장면, 폴더 이름, 우리끼리 만든 말(모아보기, 색인, 시나리오가 지도, 밖으로 나갈 것, 손 정리, 표본 60장)
- 시간 비교·오류 검사 숫자 (본문에 넣지 않는다)
- 문장마다 붙이는 단서("다만 ~는 아니다"). 꼭 밝힐 것은 안전·AI 고지에 한 번
- "실습"이나 "화면"을 홀로 쓰지 않는다. "서비스를 써 보며", "화면 캡처"처럼 무엇인지 보이게. 책은 "사용기 책"
- 표·굵은 글씨·마크다운 (본문은 일반 텍스트, 줄바꿈과 "-" 목록만). 콜론 구호, 역할 나누기 구호("정리는 AI가, 확인은 내가")

## 4. 쓸 것
- 서비스: "새로 나온 AI 에이전트 서비스", 사람이 맡긴 일을 대신 처리하는 서비스. 메일·일정이 오가는 가상 회사 업무를 맡겨 봤다
- 글쓴이: 소프트웨어 개발자, 예전에도 책을 쓴 적이 있다
- 가상 업무 시나리오: 가상 회사의 사내 워크숍 준비를 서비스에 맡기는 시나리오를 AI와 함께 짰다. 시나리오의 순서가 써 보는 단계가 됐다. 써 보는 중에 시나리오가 바뀌었고, 바꾸자고 판단·제안한 것은 사용자. 지금 찍는 시점이 맞는지 AI에게 묻기도 했다
- 방법: Claude Code를 고른 이유(컴퓨터 폴더를 통째로 맡겨 읽기·파일 옮기기·자르기까지) → 창 전체 캡처, 화면이 계속 바뀌는 부분은 녹화 → 첫날 이후 AI가 시나리오에 맞춰 단계별 폴더를 미리 만들고 사람이 캡처를 넣음, 잘못 넣은 것은 AI가 옮김 → 짧게 확인 요청 → AI가 시간순으로 읽고 무슨 화면인지 적고, 빠진 장면·가릴 개인정보를 짚음, 지우는 단계처럼 다시 찍을 수 없는 장면 앞에서 남길 화면을 알려 줌 → 화면에 없는 사정은 사람이 채팅으로 덧붙임 → 녹화 영상에서 AI가 장면을 뽑음 → 원고 쓰다 세세한 것은 AI에게 물어 기록에서 확인 → 책에 실을 그림은 AI와 고르고 사람이 공개 전에 확인
- 숫자: 직접 찍은 화면 캡처 600여 장, 녹화 25개, AI가 녹화에서 뽑은 장면 1,300여 장, 책에 실은 그림 85장, 서비스를 써 본 기간 닷새
- 결과: 사용기 책 출간. 흐름이 끊기지 않음(사용자 체감, 두 겹). 원고 쓸 때 물으면 확인됨(체감). 예전 방식이면 분량을 줄이거나 출간을 늦췄을 것(사용자 판단). 지금 블로그 글의 작은 사용기에도 쓰고, 다음 책에도 쓸 것. 쓸 때마다 방법이 나아지고 있음
- ④ 개선 포인트: 판단을 쓰는 곳을 바꿈 / 시나리오를 AI와 공유해 AI가 단계를 앎 / 사람의 확인은 책에 실릴 그림에 / 겪고 고친 것: 녹화가 원하는 창을 담았는지 바로 확인, 폴더 이름에 번호만이 아니라 무슨 단계인지 적기 / 한계: 녹화가 잘못되면 AI도 채울 수 없음
- ⑤: 짧은 단계(시나리오 짜기 → 창 전체 캡처·녹화, 시간순 저장 → 개인 화면이면 먼저 가리기 → AI에게 시간순 설명·빠진 장면·가릴 곳 → 글 쓸 때 묻고, 내보낼 그림만 직접 확인). 블로그 글 하나 같은 작은 일부터. 대상: 블로그 사용 후기, 강의 자료, 사용 설명서, 업무 매뉴얼·인수인계, 새 프로그램을 익히는 사람. 다른 사람이 해 본 적은 아직 없음. 채팅형 AI는 해 보지 않았고 시작해 볼 수 있을 것이라는 정도. 끝에 "기록만 하세요. 정리는 AI가 합니다."
- 안전: 실습용 계정, 가상 회사·인물·메일 주소 / 결제 정보 화면에서는 녹화 멈춤 / 가리기 전 원본 캡처도 AI 도구로 넘어감, 실제 개인 화면이면 먼저 가릴 것 / 책 그림은 AI가 가릴 곳을 찾고 출판 전 사람이 모두 훑어봄
- AI 고지: 기획과 가상 업무 시나리오를 AI와 의논 / 책 구성·문장은 Claude Code가 쓰고 고침 / Codex는 시나리오와 원고 검토 / 가상 메일 본문과 서비스에 보낸 요청문도 AI 도움 / 사용자는 방향을 정하고 직접 써 보고, 원고를 모두 읽고 장마다 고칠 곳을 짚음, 직접 고치지 않고 Claude Code가 모아 고치게 해 기록을 남김 / 이 글도 AI와 함께 씀

## 5. 문장

- 쉬운 한국어, 1인칭, "~습니다"체
