## 3. 말 고르기
- "실습"만 쓰지 않는다. "AI 서비스를 직접 써 보는 과정", "서비스를 써 보며"처럼 무엇을 했는지 보이게
- "화면"만 쓰지 않는다. 처음 나올 때 "서비스를 쓰는 화면", "화면 캡처"처럼 무엇인지 붙인다
- 책은 "사용기 책" (사용자가 말한 서비스 경험기)
- 대화 원문 인용, 날짜별 장면, 폴더 이름, 우리끼리 만든 말(모아보기, 색인, 시나리오가 지도, 밖으로 나갈 것, 손 정리, 표본 60장) 쓰지 않는다
- 시간 비교·오류 검사 숫자는 본문에 넣지 않는다
- 문장마다 붙이는 단서("다만 ~는 아니다")는 쓰지 않는다. 꼭 밝힐 것은 안전·AI 고지에 한 번
- 사실보다 센 말("빠짐없이", "완벽하게", "믿을 수 있다") 쓰지 않는다
- 표·굵은 글씨·마크다운 쓰지 않는다 (본문은 일반 텍스트, 줄바꿈과 "-" 목록만)

## 4. 문장 (책 작업 때 정한 규칙)
- 독자가 한 번 해석하지 않고 상황이 바로 그려지게
- 주어와 대상을 살린다. 한 문장에 사실 하나
- 쉬운 한국어, 1인칭, "~습니다"체

## 5. 줄기와 넣을 것
- ① 상황: 소프트웨어 개발자, 책을 쓴 적 있음 → 예전 책 작업 방식과 문제(사실목록 1-1) → 새 AI 서비스 사용기 책을 빨리 내야 했음, 예전 방식이면 줄이거나 늦췄을 것 → AI 글쓰기 거부감이 줄어 정리를 AI에게 맡기기로 함 → 화면으로 한 일을 글로 남기는 일은 사용 설명서·업무 매뉴얼에도 있음
- ② 방법: Claude Code를 고른 이유(폴더째 맡김) → 순서(계획을 AI와 함께 → 창 전체 캡처·녹화 → 단계 폴더에 넣기, 첫날 이후 AI가 폴더 미리 만듦 → 짧게 확인 요청 → AI가 시간순으로 읽고 무슨 화면인지 적고, 빠진 장면·가릴 개인정보 짚음, 지우는 단계 앞에서 남길 화면 알림 → 녹화에서 장면 뽑기 → 원고 쓰다 세세한 것은 AI에게 묻기 → 책에 실을 그림은 AI와 고르고 사람이 확인)
- ③ 결과: 직접 찍은 캡처 600여 장, 녹화 25개, 녹화에서 뽑은 장면 1,300여 장, 책에 실은 그림 85장 → 책 출간 → 흐름이 끊기지 않음(사용자 체감) → 물으면 확인됨(체감) → 지금 블로그 글에도 씀, 다음 책에도 쓸 것, 방식이 나아지고 있음
- ④ 나만의 방식: 기록과 정리를 나눔(찍을 때 고르지 않음) / 계획을 AI와 공유해 AI가 단계를 앎 / 사람의 확인은 책에 실릴 그림에 / 한계: 녹화가 잘못되면 AI도 못 채움, 폴더 이름을 번호로만 지으면 나중에 모름
- ⑤ 재현: 짧은 단계. 대상은 블로그·강의 자료·사용 설명서·업무 매뉴얼을 쓰는 사람, 새 프로그램을 익히는 사람. 블로그 글 하나 같은 작은 일부터. 다른 사람이 해 본 적은 아직 없음. 끝에 "기록만 하세요. 정리는 AI가 합니다." 채팅형 AI는 해 본 적 없음(시작해 볼 수 있다는 정도)
- 안전: 실습용 계정·가상 회사·인물·메일 주소 / 결제 화면 녹화 멈춤 / 가리기 전 원본이 AI 도구로 넘어감, 실제 개인 화면이면 먼저 가릴 것 / 책 그림은 AI가 가릴 곳 찾고 출판 전 사람이 모두 훑어봄
- AI 고지: 기획·계획을 AI와 의논, 책 구성·문장은 Claude Code가 쓰고 고침, Codex 검토, 사람은 방향·실습·원고 전부 읽고 고칠 곳 짚음, Claude Code가 모아 고치게 해 기록을 남김, 이 글도 AI와 함께 씀
