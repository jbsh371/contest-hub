# 초안 v2 작성 방향과 첨부 방안 (2026-10-20, 현재 판단)

## 1. v1에서 바뀌는 것

| 항목 | v1 | v2 |
|---|---|---|
| 형식 | 마크다운 (표 4개, 굵은 글씨) | **일반 텍스트**. ①~⑤ 질문을 그대로 소제목, 목록은 "-" |
| 글쓴이 | 늦게 나옴 | 첫 문단: **IT 책 6권을 낸 저자** (본업은 "개발자" 정도로만, AI 에이전트 개발은 밝히지 않음 — 기대치가 올라가고 "개발자라서 가능하다"로 읽혀 재현 용이성에 불리) |
| 상황 | 새 서비스를 써 보고 실습서를 씀 | 새 AI 서비스에 **실제 업무(워크숍 준비)를 나흘 맡겨 반응을 시험**한 기록 |
| 역할 | AI가 기록 | **남기기는 사람, 정리는 AI**, 설계(시나리오)와 확인은 사람 |
| 핵심 문장 | 정리는 AI가, 확인은 내가 | **남기는 건 내가, 정리는 AI가. 그래서 찍을 때 고르지 않는다** (시즌1 "결정은 사람이, 나머지는 AI가"와 겹침 피함) |
| 시나리오 | 거의 없음 | ④의 중심: 사람이 쓴 시나리오가 AI 정리의 기준 |
| 결과 | 기록의 질 + 숫자 | 같음 + **모든 실습 내용에 화면 근거** + **지금도 블로그·개념 공부에 계속 사용** |
| 확산 | 매뉴얼, 교육 자료, 오류 보고 | 매뉴얼·인수인계, **새 업무 도구 시험 보고**, 오류 재현 보고 (교육 자료는 강의안 수상작과 겹쳐 뺌) |
| 책 | 위키독스 무료 공개 | 제목·판매처 없이 "이 기록을 근거로 책을 써서 출간했다" |
| 뺀 것 | | 제작 기간, 업데이트 화면 이야기, 책 제목·링크 |

## 2. 칸별 계획

**사례 제목** (200자 이내) — 후보 전체와 강조 방향은 [제목후보.md](제목후보.md). 현재 추천 E:
> 캡처 2,000장과 녹화 영상을 AI가 시간순으로 정리해, 다시 할 수 없는 실습까지 빠짐없이 남긴 사례

**활용한 AI 도구** (500자 이내)
> Claude Code: 시나리오를 기준으로 캡처를 시간순 정리, 화면별 색인 작성, 그림 속 글자 분리, 필요한 부분 자르기, 가려야 할 개인정보 1차 찾기, 녹화 영상에서 장면 추출, 기록에서 찾아 답하기 / 사람이 한 일: 시나리오 작성, 캡처·녹화·실습 결과 메모, 모든 그림과 글의 최종 확인, 개인정보 가림 최종 판단

**한 줄 소개** (200자 이내)
> IT 책 6권을 쓴 저자가 실습 중엔 창 전체를 고르지 않고 찍기만 하고, 정리는 AI에게 맡겨 다시 할 수 없는 장면까지 빠짐없는 기록을 얻은 방법입니다.

**활용 사례 내용** (목표 3,000~4,000자)

| 소제목 | 평가 항목 | 들어갈 내용 |
|---|---|---|
| ① 어떤 상황에서 | 적합성 20 | 글쓴이 소개 → 집필에서 품이 드는 건 실습 기록 정리 → 예전 방식의 문제 3가지(일부 영역만 찍기, 멈춰서 메모, 녹화는 포기) → 이번 일: 새 AI 서비스에 워크숍 준비를 나흘 맡겨 반응을 시험. AI의 반응과 에이전트 만들기 같은 동작은 다시 할 수 없음 |
| ② 어떤 AI를 어떻게 | 적정성 25 | 설계(사람: 시나리오) → 남기기(사람: 창 전체 캡처, 녹화, 실습 결과 텍스트, 메모) → 정리(AI) → 확인(사람) → 다시 묻기. 도구를 고른 이유. 색인 예시 3줄(텍스트). **실제로 쓴 요청 문장 1~2개** |
| ③ 결과 변화 | 창의성·실용성 30 | 기록의 질 4가지. 숫자: 캡처 약 2,000장 → 35개 폴더와 색인, 영상에서 장면 81장, 14장+부록 그림 85장 출간. 모든 실습 내용에 화면 근거. 체감. 지금도 블로그·개념 공부에 사용 |
| ④ 나만의 방식 | 창의성·실용성 30 | 판단 미루기(찍을 때 고르지도 가리지도 않음), **시나리오가 정리의 지도이자 찍을 시점의 안내판**: AI가 시나리오를 알고 있어서 "이 단계는 지우면 다시 못 찍으니 그 전에 이 화면들을 남기세요"처럼 찍을 시점을 미리 알려 줌 (요청문장_후보.md 6절), 겪은 한계와 대처(Win + G, 글자 흐림, 프로그램 충돌, 녹화 중 AI 창, 잘라내기로 옮기다 잃어버린 캡처) |
| ⑤ 따라 하려면 | 창의성·실용성 30 | 0단계 시나리오 → 1 창 전체 찍기 → 2 폴더째 넘기며 요청 → 3 확인. 비용(캡처는 운영체제 기본 기능, AI 구독). 채팅 AI와 파일 다루는 AI의 범위 구분. 확산 3가지 |
| (끝) 안전하게 쓰기 | 윤리·책임성 25 | 실습용 계정·가상 인물, 비밀번호 화면 녹화 중지, AI 1차 찾기 + 사람 최종 가림, 글에 AI 도움 표기 |

## 3. 첨부 방안 (최대 5개, 개당 20MB)

| 순서 | 파일 | 형식 | 보여 주는 것 | 평가 항목 |
|---|---|---|---|---|
| 1 | 첨부1_사례본문_그림포함 | PDF 3~5쪽 | 본문 전체 + 역할 흐름 그림 + 전·후 비교 + 색인 예시 표. 텍스트 칸에서 못 보여 주는 표와 그림을 여기서 | 전체 |
| 2 | 첨부2_작업흐름 | PNG 1장 | 시나리오(사람) → 남기기(사람) → 정리(AI) → 확인(사람) 한눈에 | ② |
| 3 | 첨부3_전후비교_마스킹 | PNG 1장 | 창 전체 원본 캡처(가림) → AI가 자르고 가릴 곳을 찾은 결과 | ③④ |
| 4 | 첨부4_AI색인_마스킹 | PNG 또는 PDF | AI가 만든 캡처 색인 한 쪽(시각·화면 설명·가릴 곳 목록) + 35개 폴더 목록 | ②③ |
| 5 | 첨부5_시연영상 | MP4 30~60초 (선택) | 녹화 원본 → AI가 뽑은 장면 → 책에 들어간 그림 | ③ |

- 동영상은 필수가 아님. 넣지 않으면 5번 자리에 "책 본문 화면(판매 정보 없이)"을 넣음
- 모든 파일은 책 폴더에서 **복사만** 해서 이 폴더(`02_제출물/첨부/`)에서 만든다. 책 폴더는 읽기만
- 가림: 프로필, 메일 주소, 계정, 실제 이름처럼 보이는 것. 파일 이름에 "마스킹" 표기
- 화면 속 서비스 이름·로고가 보이는 곳은 최소로 (상표)
