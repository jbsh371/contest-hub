# 아이디어

바탕: [아이디어보관함 A01](../아이디어보관함.md) — AI 에이전트 기반 실습 증빙형 기술서 집필 시스템

> 이 문서의 내용은 모두 **2026-10-19 기준 현재 판단**이다. 규칙처럼 고정하지 않고, 새 정보나 상황이 바뀌면 고친다.

## 1. 한눈에 보기

| 항목 | 현재 판단 |
|---|---|
| 분야 | 업무 생산성 |
| 누구 이야기 | 실습서를 혼자 쓴 나 (구체적으로). 마지막에 업무 매뉴얼·교육 자료·블로그로 넓힘 |
| 핵심 문장 | **"고르지 않고 찍기만 한다. 정리는 AI가, 확인은 내가 한다."** |
| 핵심 원리 | 무엇이 필요한지, 무엇을 가릴지 판단하는 일을 **찍는 순간에서 정리하는 순간으로 미뤘다** |
| 대표 장면 | 회원 가입처럼 **다시 할 수 없는 실습** |
| 기록 수단 | 화면 캡처(주) + 동영상 녹화(확실할 때). 그림으로 못 담는 상황은 채팅으로 덧붙임 |
| 결과 변화 | 시간 수치 대신 **기록의 질** 4가지 + 솔직한 체감 + 셀 수 있는 결과물 |
| 말투 | 쉬운 말. 도구는 사실대로, 재현은 누구나 할 수 있는 방법으로 |
| 제목 | 미정 (추천 D) |

## 2. 사용자가 실제로 한 방식

1. 실습 시나리오대로 실행하면서 **창 전체**를 캡처한다. 녹화가 확실할 때는 동영상으로 녹화한다.
2. 장 하나를 끝내면 캡처 10~30장(또는 영상)을 **폴더째** AI에게 넘긴다.
3. AI가 시간 순서대로 그림을 분석하고, 그림 속 내용과 글자를 나눠 기록한다.
4. 그림으로 전할 수 없는 상황은 채팅창에 한두 줄로 덧붙인다.
5. 동영상은 AI가 필요한 장면을 이미지로 뽑아 준다.
6. AI가 필요한 부분만 잘라 주고, 시간순 정렬·항목별 묶기를 한다.
7. 개인정보·저작권이 걸리는 곳은 **AI가 먼저 걸러 내고, 사람이 최종 확인**한다.
8. 모든 그림과 글은 사람이 확인한다.
9. 글을 쓰다 기억나지 않는 부분은 AI에게 물으면 기록에서 찾아 준다.

## 3. 전·후 비교

| | 예전 | 지금 |
|---|---|---|
| 캡처 범위 | 개인정보 때문에 **일부 영역만** 찍음 | **창 전체**를 찍음. 가리기는 AI가 먼저, 확인은 사람 |
| 캡처 판단 | "이 화면은 필요 없겠지" 하고 넘김 → 나중에 필요하거나 기억나지 않음 | **고르지 않고** 다 찍음 |
| 동영상 | 장면을 뽑기 힘들어 **엄두도 못 냄** | 녹화본을 넘기면 AI가 장면을 뽑아 줌 |
| 실습 흐름 | 단계마다 멈추고 메모 | 찍기만 하고 계속 진행 |
| 정리 | 자르기·정렬·가리기를 손으로 | AI가 하고 사람이 확인 |

## 4. 결과 변화: 기록의 질 4가지 (작업 흐름 순서)

| 효과 | 내용 |
|---|---|
| 1. 실습이 끊기지 않는다 | 기록하느라 멈추지 않음 |
| 2. 기록이 빠지지 않는다 | 다시 할 수 없는 실습도 모든 장면이 순서대로 남음 |
| 3. 필요할 때 다시 꺼낸다 | 기억이 흐려도 AI에게 물으면 기록에서 찾아 줌 |
| 4. 정리는 AI, 확인은 사람 | 정렬·자르기·가리기를 AI가 하고 사람이 확인해 정확해짐 |

- 사용자 원래 표현: 빠짐없는 기록, 빈틈없는 기록, 물으면 명확히 답하는 기록, 오차 없는 데이터 정리
- "오차 없는"은 단정하지 않는다 (AI도 틀릴 수 있음) → 4번처럼 씀
- 체감은 체감대로 쓴다: 창별 캡처 + 직접 자르기와 "비교할 수 없을 만큼 빠르다"
- 시간 수치: 지금은 추정할 수 없어 쓰지 않음. 측정할 방법이 생기면 넣는다
- 숫자는 셀 수 있는 것만: 한 번에 넘긴 캡처 10~30장, 14장짜리 책 공개, 그림·영상 수 (책 폴더에서 확인 후 사용)

## 5. 솔직하게 쓸 한계 (사용자 경험 범위로)

| | 화면 캡처 | 동영상 녹화 |
|---|---|---|
| 쓰임 | 주로 사용 | 녹화가 확실하다고 판단될 때 |
| 장점 | 안정적 | 모든 장면이 이어서 남음 |
| 주의 | 찍는 순간을 놓칠 수 있음 | 실제로 녹화되지 않는 경우가 있었음 → 녹화 프로그램을 잘 알아야 함 |

- "제 경우에는" 캡처와 녹화 프로그램을 함께 켜면 충돌해 하나를 골라 썼다 (모든 환경을 시험한 것은 아님)

## 8. 제목 후보

- A. 실습하며 메모하지 않았다, 캡처만 했더니 AI가 빠짐없이 기록했다
- B. 캡처 30장을 AI에게 넘기면 실습 기록이 끝난다
- C. 메모 없는 실습: AI 기록 비서와 실습서 한 권을 쓰다
- **D. 다시 할 수 없는 실습도 빠짐없이: 고르지 않고 찍었더니 AI가 정리했다** (추천)

한 줄 소개 초안: 실습 중엔 창 전체를 찍기만 하고, 정리·자르기·개인정보 거르기는 AI에게 맡긴 뒤 직접 확인해 빠짐없는 실습 기록으로 책을 썼습니다.

## 8-1. 틀 다시 보기 (2026-10-19 논의 중)

사용자 질문: 책은 빠지나? 실습서로 시작하면 딱딱하지 않나? 글 작성인가 업무 생산성인가? 모든 기록이 업무인가? 시나리오가 없어도 캡처는 유용하지 않나 (시간 순서가 있으니)?

제안 (사용자 동의 전):
| 층 | 내용 |
|---|---|
| 주제 (넓게) | **화면으로 하는 일을 기록하는 방법** — 컴퓨터로 일하는 누구나 |
| 증거 (구체적으로) | 이 방법으로 책 한 권을 썼다 → 책은 빠지지 않고 "결과이자 증거"로 들어감 |
| 확장 | 업무 매뉴얼, 작업 보고서, 자료 조사·기초자료 모으기 |

- 시작은 실습서가 아니라 누구나 겪는 장면: "그때 그 화면이 뭐였지?", "이건 필요 없겠지 하고 안 찍었는데…"
- 분야: 업무 생산성 유지. 모든 기록이 업무는 아니지만, 이 사례는 기록을 **결과물(책·매뉴얼·보고서)로 만드는 과정**을 바꾼 것 → "업무 프로세스 개선"에 해당
- 시나리오: 필수가 아님. 기록을 묶어 주는 건 **시간 순서**. 시나리오가 있으면 AI가 단계에 맞춰 정리하기 더 쉬움
- 시나리오 없이 쓴 경험이 있는지 확인 필요 (있으면 확장 근거로 씀)
- **확장은 평가 항목이다** (③ 창의성·실용성 30점 중 "기대효과의 구체성, 확산 가능성") → 마지막 한 줄이 아니라 독립된 부분으로 쓴다
  - 사례 본문(해 본 것)과 확장(적용할 수 있는 곳)을 나눠, 확장은 "~에 적용할 수 있다"로 쓴다
  - 넓게 늘어놓지 않고 2~3개를 "누가, 어떤 상황에서, 무엇이 좋아지는지"로 구체적으로 쓴다
  - **현재 판단 (사용자 의견 반영)**: 확산은 실습에서 자연스럽게 이어지는 방향으로 간다 — "화면에서 단계별로 한 일을 기록해 문서로 만드는 일"
    | 확산 | 이어지는 이유 |
    |---|---|
    | 업무 매뉴얼·인수인계 문서 | 실습서와 같은 구조 (단계 + 화면). 업무 생산성 분야와 바로 맞음 |
    | 교육·연수 자료 | 시연 한 번으로 단계별 자료 |
    | 오류 재현 보고 | 한 번뿐인 실습과 같은 원리 (다시 만들기 어려운 상황) |
    - 자료 조사·관공서 신청은 실습과 거리가 멀어 뺀다 (논의 기록으로만 남김)
    - 이에 따라 주제도 "실습(단계별 작업) 기록 → 문서"로 다시 좁힘. 책은 그 첫 사례이자 증거. 시작 장면만 딱딱하지 않게
  - 이전 후보 (논의 기록):
    | 대상 | 상황 | 좋아지는 점 |
    |---|---|---|
    | 직장인 | 새 시스템 사용법·업무 인수인계 매뉴얼 | 일하면서 찍기만 하면 매뉴얼 초안이 남음 |
    | IT·고객지원 | 오류가 난 과정 보고 | 다시 재현하기 어려운 오류도 순서대로 남음 |
    | 강사·교사 | 수업용 실습 자료 | 한 번 시연하면서 찍은 것으로 단계별 자료 |
    | 누구나 | 자료 조사·기초자료 모으기 (시나리오 없음) | 시간 순서로 무엇을 봤는지 다시 찾을 수 있음 |
    | 누구나 | 관공서·은행 등 한 번뿐인 온라인 신청 | 나중에 "뭘 입력했더라?"를 찾을 수 있음 (개인정보 주의) |

## 8-2. 사용자 정보 (2026-10-20)

- 직업: SW 개발자, 주로 AI 에이전트 개발. 틈틈이 AI 관련 책 집필, **지금까지 6권 출간**
- 시간: 예전 IT 기술서는 한 권에 몇 개월. AI를 쓰면서 점점 줄어 직전 책은 약 2달. 이번 책은 기술서가 아니라 서비스 경험담이라 직접 비교는 어려움 (사용자 판단)
  - 참고: 책 작업 기록상 실습 10-07~10-11, 원고 작업은 주로 10-13~10-15 (git 기록). "실습부터 공개까지 약 열흘"로 쓸 수 있는지 사용자 확인 필요
- 지금도 쓰는지: **블로그 작성, 개념을 이해할 때 계속 쓴다. "아주 편하다"**
- **기록의 범위 (현재 판단)**: 남기기 = 사람 (캡처, 녹화, 실습 결과 텍스트, 상황 메모, 시나리오 작성) / 정리 = AI (시간순 정렬, 색인, 글자 분리, 자르기, 개인정보 1차 찾기, 영상 장면 추출, 물으면 찾아 답하기) / 확인 = 사람. "기록을 AI에게 맡겼다"가 아니라 **"기록은 내가 남기고, 정리는 AI가 했다"**
- **책 제작 기간은 쓰지 않는다 (현재 판단)**: "책을 열흘 만에 썼다"는 AI 집필에 대한 거부감을 부르고, 이 사례의 주장(기록이 빠지지 않는다)과도 관계없음. 결과는 기록의 질로만 말함. 책은 "이 기록을 근거로 책을 써서 공개했다"까지만. 거짓이나 오해를 부르는 표현은 쓰지 않고, 주최 측이 물으면 AI 활용을 그대로 설명
  - 대신 쓸 사실: 책에 들어간 모든 실습 내용은 화면 근거가 있음 (실습의 신뢰성)
  - 뺀 것: "업데이트로 화면이 바뀌니 다시 못 찍는다" → 사용자 의견: 독자에게는 최신 화면이 더 필요하므로 맞지 않음. 한 번뿐인 장면은 "AI의 반응"과 "한 번만 할 수 있는 동작(dot 만들기 등)"으로 설명
- **책 제목·판매 링크 (현재 판단)**: 본문에 넣지 않는다. 판매 링크는 공개 게시판에서 홍보로 보일 수 있고, 책 제목으로 실명이 드러나며, AI 집필에 대한 거부감이 책으로 이어질 수 있음. 증거는 첨부(책 화면 캡처)와 숫자로 충분. 주최 측이 물으면 그때 알림
  - 사실 확인 (2026-10-20 사용자): 위키독스에서 판매하며 무료 공개 범위는 아주 작게 함. 위키독스를 통해 교보·예스24에도 판매
